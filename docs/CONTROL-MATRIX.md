# Control Traceability Matrix — ISO/IEC 27001:2022 Annex A (A.8.26)

> This is the traceability matrix required by plan §8.1 row A.8.26: every security requirement in
> plan §8.1 mapped to its implementation and its acceptance test. Control IDs and names are taken
> verbatim from the client's copy of ISO/IEC 27001:2022, Annex A, Table A.1, as reproduced in the
> plan. One row per plan §8.1 row — nothing omitted.
>
> **Status legend:**
> - **Implemented** — built and testable now (Phase 0 scope).
> - **Partial** — some acceptance criteria met now; the remainder has a named phase or owner below.
> - **Deferred (Phase N)** — deliberately scheduled to a later phase; recorded here, not silently skipped (plan §8.3.4).
> - **Client decision** — blocked on an open question in `/docs/ASSUMPTIONS.md`.
> - **Organisational (Massy)** — a deployment/ISMS control owned by Massy; the app documents and supports it.
>
> Implementation paths refer to the server workspace being built concurrently; paths are the agreed
> conventions for this repo. Last updated: 2026-08-04.

## Compliance definition of done (plan §8.3)

A feature is **not done** until all four hold:

1. **It has a test.**
2. **Every applicable row in plan §8.1 has been checked against it.**
3. **This file (`/docs/CONTROL-MATRIX.md`) is updated** with the control → code → test mapping for the feature.
4. **If a control could not be satisfied, it is recorded as an exception** — with a reason and an owner — in this file and in `/docs/ASSUMPTIONS.md`. **Never silently skipped.**

Current recorded exceptions/deferrals: A.5.13, A.8.7, A.8.11, A.8.12 (feature not yet built —
phases 2–3); A.8.13 restore drill and A.8.29 pen test (Phase 4); A.5.31 and parts of A.5.16/A.8.5
(client decisions — see `/docs/ASSUMPTIONS.md`); A.8.20/A.8.21/A.8.22 and at-rest encryption
(Massy deployment controls). Owner for all deferrals: development lead, reviewed at each phase gate.
