# Control Traceability Matrix — ISO/IEC 27001:2022 Annex A (A.8.26)

> This is the traceability matrix required by plan §8.1 row A.8.26: every security requirement in
> plan §8.1 mapped to its implementation and its acceptance test. Control IDs and names are taken
> verbatim from the client's copy of ISO/IEC 27001:2022, Annex A, Table A.1, as reproduced in the
> plan. One row per plan §8.1 row — nothing omitted.
>
> **Status legend:**
> - **Implemented** — built and covered by an automated test now (Phase 0 scope).
> - **Partial** — some acceptance criteria met now; the remainder has a named phase or owner below.
> - **Deferred (Phase N)** — deliberately scheduled to a later phase; recorded here, not silently skipped (plan §8.3.4).
> - **Client decision** — blocked on an open question in `/docs/ASSUMPTIONS.md`.
> - **Organisational (Massy)** — a deployment/ISMS control owned by Massy; the app documents and supports it.
>
> Every row below was adversarially verified against the actual code and tests: a multi-agent
> control-by-control review of Phase 0 (2026-08-04), and a six-lens adversarial review of Phases
> 1–3 (2026-08-05) in which every claimed defect was independently refuted or confirmed against
> the code. The 21 confirmed Phase 1–3 defects were fixed the same day in
> `server/migrations/0010_review_fixes.sql` and the corresponding routes, each with a regression
> test; the judgement calls taken while fixing are recorded in `docs/ASSUMPTIONS.md` §2.19.
> Last updated: 2026-08-06 (Phases 1–3 + review fixes + §6.1 activation-review visibility).

## Compliance definition of done (plan §8.3)

A feature is **not done** until all four hold:

1. **It has a test.**
